# Alert Bot

Телеграм-бот для двух задач:

1. **Сигналы оповещения** — воздушная тревога, морская опасность и их отбои. Источников два: канал в телеграме и **стена ВКонтакте** того же автора. Сигнал публикуется заранее заданным шаблоном.
2. **Отключения электроэнергии** — мониторит канал энергетиков (Севастопольэнерго), с помощью LLM извлекает график веерных отключений (очередь + время) и публикует красиво оформленный пост с адресами, взятыми дословно из исходного поста.

Обе задачи публикуют **параллельно в Telegram и в MAX Messenger**. Юзербот только **читает** каналы, публикация идёт через официальный **Bot API** (гибридный режим — безопаснее для аккаунта).

> **Почему два источника сигналов.** С августа 2026 автор публикует в телеграм нестабильно и с опозданием, а часть сигналов выкладывает **картинкой без подписи** — такие посты фильтр по тексту не видел вовсе. В ВК те же сигналы появляются раньше, поэтому стена ВК читается как равноправный источник, а картинки-плашки распознаются (см. ниже).

## Возможности

- Мониторинг трёх источников с независимыми циклами (ни ВК, ни энергоканал не влияют на скорость выдачи тревог).
- **Сигналы:** сопоставление по ключевым фразам (фраза в начале текста, игнорируются эмодзи, регистр, `!`) → публикация статичного шаблона.
- **Виды сигналов задаются данными:** файл фраз + шаблон в `.env`. Новый сигнал добавляется без правки кода.
- **Распознавание картинок-плашек:** знакомые узнаются по перцептивному хешу мгновенно и бесплатно, незнакомая уходит в vision-модель, а её хеш дописывается в эталоны.
- **Дедуп по состоянию сигнала:** одна и та же тревога из двух источников публикуется один раз, а настоящая повторная (после отбоя) проходит.
- Уведомление администратору, если текст похож на сигнал, но не совпал ни с одной фразой — защита от тихого отказа при смене формулировок.
- **Энергоканал:** LLM-извлечение структуры (тип / очередь / время) + сверка с текстом поста (защита от ошибок модели) + адреса дословно из самого поста.
- Параллельная публикация в Telegram + MAX; если один канал упал — второй всё равно получит.
- Защита от дубликатов (обработанные ID хранятся по каждому каналу отдельно).
- Автопереподключение к Telegram, пропуск устаревших постов после рестарта, уведомления администратору о сбоях.

## Как это работает

### 1. Сигналы оповещения
1. Каждые ~30 сек бот читает последние посты канала-источника (`SOURCE_CHANNEL`) и, независимым циклом, стену ВК (`VK_DOMAIN`).
2. Текст нормализуется (убираются эмодзи, `!`, регистр, лишние пробелы).
3. Если текст **начинается** с фразы из файла какого-либо сигнала — публикуется шаблон этого сигнала.
4. **Пост без текста, но с картинкой** (только ВК): картинка сверяется с эталонами из `data/plates` по перцептивному хешу. Совпала — берётся её надпись; не совпала — картинку читает vision-модель, а распознанный текст проходит тот же фильтр по ключевым фразам. Новая плашка после успешного распознавания сохраняется в эталоны, и дальше узнаётся мгновенно.
5. Шаблон уходит в `TARGET_CHANNEL` (Telegram) и в MAX.

**Виды сигналов** (`Config.signals()`): воздушная тревога и её отбой — группа `air`; морская опасность и её отбой — группа `sea`. Группы независимы: морской отбой не отменяет воздушную тревогу. Сигнал с пустым шаблоном не подключается — так его можно держать выключенным, не удаляя фразы.

**Защита от дублей.** Помнится действующее состояние каждой группы (`data/signal_state.json`), публикуется только переход: тревога после отбоя, отбой после тревоги. Поэтому одна и та же тревога, пришедшая из ВК и через минуты из телеграма, публикуется один раз. У состояния есть срок годности `SIGNAL_DEDUP_SECONDS`: если отбой будет пропущен, состояние не заглушит следующую тревогу навсегда.

> Что делать, если источник изменил формулировку: бот пришлёт администратору текст, который похож на сигнал, но не совпал ни с одной фразой. Достаточно дописать строку в соответствующий `data/keywords_*.txt` и перезапустить сервис.

### 2. Отключения электроэнергии
1. Отдельный цикл читает канал `ENERGY_SOURCE_CHANNEL`.
2. Текст нового поста отправляется в LLM (через OpenAI-совместимый шлюз, напр. vsellm.ru), который возвращает строгий JSON:
   `{"type": "outage|lifted|ignore", "confirmed": bool, "windows": [{"queue": 1|2, "from": "ЧЧ:ММ|null", "to": "ЧЧ:ММ"}]}`
3. Код **валидирует** и **сверяет** извлечённые очередь/время с текстом поста. Не сошлось — пост не публикуется, а черновик уходит администратору в личку.
4. Публикуется **только `outage`** (веерное отключение по графику очереди):
   - `confirmed=true` → «🔌 Отключение электроэнергии — N очередь»
   - `confirmed=false` → «⚠️ Ожидается отключение электроэнергии — N очередь»
   - к посту добавляется блок адресов, **вырезанный дословно из исходного поста** (Севастопольэнерго меняет адреса от поста к посту, поэтому локальные списки не используются); если формат поста изменится и адреса вырезать не удастся — публикуются очередь и время без адресов. Плюс подпись источника.
5. Игнорируются (не публикуются): снятие/восстановление, технологические нарушения и аварии, плановые/ремонтные работы по адресам, локальные отключения без очереди, новости и реклама.

> Итоговый пост собирает **код**, а не LLM — модель отвечает только за извлечение полей. Это исключает попадание «галлюцинаций» в готовый текст.

## Архитектура

```
main.py — AlertBot: три независимых asyncio-цикла
  ├─ цикл телеграма    → process_new_posts    (SOURCE_CHANNEL)
  ├─ цикл ВК           → process_vk_posts     (VK_DOMAIN)              [фоновая задача]
  └─ цикл энергоканала → process_energy_posts (ENERGY_SOURCE_CHANNEL)  [фоновая задача]
  └─ src/
     ├─ config.py            — конфигурация из .env + validate() + signals()
     ├─ parser.py            — чтение постов телеграма (telethon) с таймаутами
     ├─ vk_parser.py         — чтение стены ВК (wall.get) + скачивание картинок
     ├─ filter.py            — TextFilter: нормализация + опознание вида сигнала
     ├─ plate_recognizer.py  — картинки-плашки: перцептивный хеш + эталоны
     ├─ vision_recognizer.py — чтение надписи с незнакомой картинки (vision LLM)
     ├─ signal_state.py      — действующее состояние сигналов (дедуп)
     ├─ llm_extractor.py     — LLMExtractor + verify_outage (энергопосты)
     ├─ energy_formatter.py  — сборка поста об отключении + адреса
     ├─ bot_publisher.py     — публикация в Telegram через Bot API
     ├─ publisher.py         — публикация через userbot (запасной путь)
     ├─ max_publisher.py     — публикация в MAX Messenger
     ├─ storage.py           — обработанные ID по каналам (+ asyncio.Lock)
     └─ logger.py            — логирование
```

**Изоляция:** энергоканал крутится в отдельной фоновой задаче. Сетевой запрос к LLM (`await`) уступает управление, поэтому медленный/зависший вызов модели **не задерживает** проверку тревог. Общий файл обработанных ID защищён локом.

## Установка

```bash
cd alert_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # затем заполнить .env
```

При первом запуске потребуется авторизация userbot: номер телефона → код из Telegram → при необходимости пароль 2FA.

## Конфигурация (`.env`)

### Telegram / userbot
| Переменная | Описание |
|---|---|
| `API_ID`, `API_HASH` | ключи с https://my.telegram.org/apps |
| `PHONE` | номер телефона userbot (с кодом страны) |
| `SOURCE_CHANNEL` | канал-источник тревог (напр. `@razvozhaev`) |
| `TARGET_CHANNEL` | целевой канал публикации (напр. `@nts_novosti`) |
| `CHECK_INTERVAL` | интервал проверки, сек (по умолчанию 30) |
| `RANDOM_DELAY`, `DELAY_VARIANCE` | случайный разброс интервала |

### Публикация
| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather (гибридный режим — публикация через Bot API) |
| `ADMIN_CHAT_ID` | Telegram-ID администратора для уведомлений о сбоях и черновиков |
| `MAX_BOT_TOKEN` | токен бота MAX (пусто — MAX отключён) |
| `MAX_TARGET_CHANNEL` | chat_id целевого канала MAX |

### Шаблоны сигналов
| Переменная | Описание |
|---|---|
| `KEYWORDS_ALERT_FILE`, `KEYWORDS_CLEAR_FILE` | файлы ключевых фраз воздушной тревоги |
| `ALERT_TEMPLATE`, `CLEAR_TEMPLATE` | тексты шаблонов (HTML: `<b>`, `<i>`) |
| `KEYWORDS_SEA_ALERT_FILE`, `KEYWORDS_SEA_CLEAR_FILE` | файлы фраз сигнала «Морская опасность» |
| `SEA_ALERT_TEMPLATE`, `SEA_CLEAR_TEMPLATE` | шаблоны морской опасности; **пусто — сигнал не публикуется** |
| `SIGNAL_DEDUP_SECONDS` | срок годности состояния сигнала, сек (по умолчанию 1800) |

> В шаблоне с переносами строк значение берите в двойные кавычки, тогда `\n` сработает как перенос.

### Источник ВКонтакте
| Переменная | Описание |
|---|---|
| `VK_SERVICE_TOKEN` | сервисный ключ приложения (dev.vk.ru → Мои приложения → Standalone); пусто — источник отключён |
| `VK_DOMAIN` | короткое имя страницы: `vk.ru/<domain>` |
| `VK_CHECK_INTERVAL` | интервал опроса стены, сек (по умолчанию — как `CHECK_INTERVAL`) |
| `VK_API_VERSION` | версия API ВК (по умолчанию `5.199`) |
| `PLATES_DIR` | каталог эталонов картинок-плашек (по умолчанию `data/plates`) |
| `VISION_MODEL` | модель для чтения незнакомой картинки; использует `LLM_API_KEY` и `LLM_BASE_URL` |

> Пуш-событий для чужой стены ВК не даёт (Callback API доступен только администратору своего сообщества), поэтому источник опрашивается так же, как телеграм.

### Энергоканал (второй источник)
| Переменная | Описание |
|---|---|
| `ENERGY_SOURCE_CHANNEL` | канал энергетиков (напр. `@sev_energo`); пусто — функция отключена |
| `LLM_API_KEY` | ключ LLM-шлюза (напр. vsellm.ru) |
| `LLM_BASE_URL` | базовый URL, по умолчанию `https://api.vsellm.ru/v1` |
| `LLM_MODEL` | модель, напр. `openai/gpt-4.1-mini` |
| `QUEUE_1_ADDRESSES_FILE`, `QUEUE_2_ADDRESSES_FILE` | файлы адресов по очередям |
| `ENERGY_SOURCE_NAME` | подпись источника в постах (текстом) |
| `ENERGY_LIFTED_ENABLED` | публиковать посты о снятии ограничений (по умолчанию `false`) |

> Энергоканал включается только если заданы **и** `ENERGY_SOURCE_CHANNEL`, **и** `LLM_API_KEY`.
> Рекомендуемая модель — не «думающая» (напр. `gpt-4.1-mini`): reasoning-модели тратят лимит токенов на внутренние рассуждения и могут вернуть пустой ответ.

## Логи

Пишутся в `logs/bot_YYYYMMDD.log` (имя — по дате запуска процесса) и в stderr сервиса.

Полезные выборки:
```bash
# события энергоканала
grep -i энергопост logs/bot_$(date +%Y%m%d).log
# ошибки/сбои
grep -iE "ошибк|traceback|невалидн" logs/bot_$(date +%Y%m%d).log
```

## Обновление на сервере

```bash
cd ~/projects/bots/alert_bot
git pull
# при изменении зависимостей:

```

Файлы `.env`, `*.session`, `data/processed_posts.json` в `.gitignore` — при обновлении не затрагиваются. Формат `processed_posts.json` мигрирует автоматически.

## Безопасность

- Никогда не коммитьте `.env`, session-файлы и токены (уже в `.gitignore`).
- `API_HASH` и session-файлы содержат данные авторизации — храните в секрете.
- Списки адресов и шаблоны (`data/*.txt`) можно править без изменения кода — после правки перезапустите сервис.
